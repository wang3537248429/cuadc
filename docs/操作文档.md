# 操作文档

本文适用于完整 CUADC 源码包。除特别说明外，命令从仓库根目录执行。模块与目录职责见[项目结构](项目结构.md)。

## 1. 环境与依赖

| 组件 | 仿真使用版本或要求 |
| --- | --- |
| 操作系统 | Ubuntu 22.04 amd64 |
| Python | 3.10 |
| ROS 2 | Humble；图像桥为 `ros_gz_bridge` |
| Gazebo | Garden，Sim 7.9.x |
| 飞控 | ArduPlane 4.6.3 SITL |
| ArduPilot 提交 | `3fc7011a7d3dc047cbb17d8bd98ee94577d144c6` |
| ArduPilot Gazebo 插件提交 | `082a0fe231f6e63bc8d1598f1cba461d9e2ea7f5` |
| Python 运行依赖 | `gazebo_sim/requirements.lock.txt` |
| YOLO | Ultralytics 8.4.106 |
| MAVLink | pymavlink 2.4.49，MAVProxy 1.8.74 |
| 图形界面 | PySide6-Essentials 6.11.1、可用 OpenGL 与桌面显示会话 |
| Mission Planner | 单独安装，推荐 Windows；本项目通过 MAVLink UDP 通信 |

首次安装需联网获取系统包、Python 包和固定提交源码，并预留至少 20 GB 磁盘。CPU 推理不要求 CUDA。Gazebo、ROS 软件源的可用性取决于上游服务；若软件源下线，应先恢复对应版本来源，不能把其他 Gazebo 大版本当作已验证替代。

完整 Python 锁适用于仿真 amd64 环境；树莓派使用 `onboard/requirements.txt`，不套用桌面 CPU wheel。各模块 `pyproject.toml` 声明直接依赖与命令入口。

## 2. 安装仿真环境

先按[资源与许可](资源与许可.md)准备有权使用的本地靶标图片。公开源码随附两套运行权重归档，安装脚本会校验并解压；没有靶标图片时不能完成在线识别与飞行任务。

```bash
sudo ./gazebo_sim/scripts/install_system_deps.sh
./gazebo_sim/scripts/check_environment.sh
python3 scripts/check_local_resources.py --project gazebo_sim --require
./gazebo_sim/scripts/bootstrap.sh
```

系统安装脚本配置 ROS 与 Gazebo 软件源并安装依赖。`bootstrap.sh` 获取固定版本 SITL 和插件、应用补丁、创建虚拟环境、安装锁定依赖并构建本项目插件。完成后保留 `.deps/runtime/` 中的运行文件，清理下载源码与中间构建目录。它不会从未知来源自动下载权重。

干净源码包没有靶标图片时，使用 `./gazebo_sim/scripts/bootstrap.sh --no-vision`。该选项只安装基础仿真依赖，随后用 `./gazebo_sim/scripts/run_sim.sh --no-vision --seed 1` 启动一个不带纹理、不执行 YOLO 的可加载场景，便于新机器先验证 Gazebo、ArduPlane 和 MAVLink 链路。完整模式仍需准备合法资源，不能用无视觉模式代替识别验收。

重要位置：

| 路径 | 内容 |
| --- | --- |
| `gazebo_sim/.venv/` | 仿真 Python 环境 |
| `gazebo_sim/.deps/runtime/` | SITL 与上游 Gazebo 插件 |
| `gazebo_sim/.runtime/plugins-build/` | 本项目插件构建结果 |
| `gazebo_sim/models/vision/` | 本地 YOLO 权重与校验清单 |

## 3. 可视化启动与退出

A 区：

```bash
./gazebo_sim/scripts/run_sim.sh --official-route A
```

B 区：

```bash
./gazebo_sim/scripts/run_sim.sh --official-route B
```

默认打开 Gazebo 图形窗口与视觉窗口。启动时生成新的随机种子，重新抽取目标内容和空井分配。排查问题需要复现时再显式增加 `--seed 12345`；不要将固定种子的结果写成随机任务验收。

等待终端提示 Mission Planner 使用 UDP 14550。上传任务后，等待状态变为 `READY`，再从地面站执行飞行。

自动化源码检查不需要显示会话；完整仿真的无图形启动使用 `--headless`，相机与 YOLO 仍然运行。本地验收需要观察飞行时应保留默认图形模式。

在启动终端按 `Ctrl+C` 退出。supervisor 处理 SIGINT/SIGTERM，在退出时回收本次创建的 Gazebo、视觉、SITL、路由及任务子进程。任务完成状态本身不等于所有进程已经关闭，测试后仍需退出 supervisor。

再次测试前检查：

```bash
pgrep -af 'cuadc_sim|arduplane|mavproxy' || true
ss -lunpt | rg '14550|5810|9052|8765' || true
```

如有残留，先核对 PID 的启动命令与工作目录，再对该进程发送 TERM；不要使用会结束其他工程的全局进程名清理。保存需要的日志后再清理 `.runtime/`。

## 4. 连接 Mission Planner

从 [ArduPilot 官方页面](https://ardupilot.org/planner/docs/mission-planner-installation.html)安装 Mission Planner。与仿真同机运行时选择 UDP，端口为 `14550`。

若地面站在另一台电脑上，仿真启动时增加 `--gcs-host`，其值为地面站电脑的局域网 IPv4；检查两端防火墙允许该 UDP 通信。真实地址只用于本地，不写入公共配置。

操作顺序：

1. 在 PLAN 中载入与所选区域一致的航线文件。
2. 核对 HOME、航点顺序、高度和指令，点击 Write WPs。
3. 从飞控读回航点，检查数量与内容。
4. 等待任务状态由 `WAITING_FOR_MISSION` 进入 `READY`。
5. 通过 Mission Planner 选择 AUTO 并执行解锁，观察起飞、识别、投水与返航。
6. 降落停稳后检查结果，退出启动终端中的仿真进程。

A/B 文件与公开坐标说明见[航线配置](航线配置.md)。场地参数只选择仿真布局，任务仍须由地面站上传。动态模式使用任务预留条目，系统不会把场景目标中心当作识别结果。

Mission Planner 的参数 `SCR_USER1` 选择任务：1 为图形类别，2 为两位数字；`SCR_USER2` 选择区域：0 为 A，1 为 B。修改任务后检查状态中的任务、区域与模型一致，不在同一任务过程中混用区域配置。

## 5. YOLO 与任务记录

Task 1 使用 `task1_v4m_best.pt`，Task 2 使用 `task2_sim_digits_v1.pt`。视觉服务处理相机帧，像素候选区域用于预处理，类别由 YOLO 输出。参考图片用于场景生成，场景真值用于评分；在线识别不应以真值代替检测。

主要输出：

| 路径 | 用途 |
| --- | --- |
| `gazebo_sim/.runtime/vision_state.json` | 视觉检测与状态 |
| `gazebo_sim/.runtime/route_state.json` | 航点、遥测轨迹和任务状态 |
| `gazebo_sim/.runtime/logs/` | Gazebo、视觉、飞控与任务进程日志 |
| `gazebo_sim/runs/latest.json` | 最近一次任务结果 |
| `gazebo_sim/runs/` | 分次保存的任务结果 |

验收至少核对任务状态、任务与区域、YOLO 检测、选靶理由、实际释放、物理落点、返航和停稳。结果中的 `source=YOLO`、`recognition_complete=true`、`guessed=false` 用来检查识别来源；还需核对模型身份与实际检测内容。

`DYNAMIC_BALLISTIC` 表示动态投水来源，`MISSION_PLANNER_RAW_COMMAND` 表示原任务中的固定释放。固定释放执行成功不能作为动态精度通过的证据。测试必须报告实测落点与规则判定，不能只凭窗口中的投水效果判断。

## 6. 完整任务验证

准备完整合法资源和环境后，先启动图形仿真：

```bash
./gazebo_sim/scripts/run_sim.sh --official-route A
```

在另一个终端执行：

```bash
./gazebo_sim/.venv/bin/python gazebo_sim/scripts/e2e_smoke.py \
  --task 1 --group A \
  --mission gazebo_sim/config/missions/official_route_a.waypoints \
  --full --timeout 480 --require-dynamic-release
```

回归工具通过 MAVLink 执行任务上传与完整流程。运行它时断开 Mission Planner，避免两个客户端同时写入任务。Task 2 将 `--task` 改为 2；B 区同时改为 B 场地、B 分组和 B 航线。每次测试结束后退出 supervisor，再开始下一次。

每个任务与区域至少保存所用种子、资源校验值、结果文件和失败原因。更换模型、图片、场地或航线后重新验证；旧结果不作为新配置的通过依据。当前公开源码没有附带这组完整资源的飞行合格报告。

## 7. 机载环境

安装器支持树莓派 4B、Ubuntu 22.04 aarch64。先准备有权使用的权重，以普通用户运行：

```bash
./onboard/scripts/install_onboard.sh
```

安装后重新登录，使 `dialout`、`video` 用户组生效。核对 `onboard/config/onboard.yaml` 中的相机、串口、任务、模型与释放机构设置，再执行：

```bash
onboard/.venv-onboard/bin/cuadc-onboard \
  --config onboard/config/onboard.yaml check
```

设备标识和真实运行设置保存到本地配置，不能提交个人串口序列号。桌面离线检查可使用 `check --allow-non-pi --skip-camera`，该结果不代表硬件已通过。服务部署与维护入口在 `onboard/scripts/`，开发说明见 [DEVELOPMENT.md](../onboard/DEVELOPMENT.md)。

机载生产程序不负责解锁或启动飞行任务。相机安装角、时间同步、串口与执行机构均需在实际硬件验证，仿真结果不能替代这些检查。

## 8. 中文监控与日志回放

```bash
sudo apt-get install python3-tk
python3 -m venv ground_station/.venv
source ground_station/.venv/bin/activate
python -m pip install -e ./ground_station
./ground_station/run.sh
```

该工具读取遥测和 TLOG，Mission Planner 继续负责航点上传与飞控操作。Windows 构建入口为 `ground_station/build_windows.bat` 和 `build_windows.ps1`，依赖见该目录的 `requirements-build.txt`。

TLOG 和回放文件仅本地保存，公开前检查其中的位置、设备和操作者信息。

## 9. 源码检查与发布

不需要视觉模型的测试环境安装方法见[README](../README.md)。完整本地环境执行：

```bash
./scripts/verify_release.sh
```

脚本检查公开文件隐私、Shell 语法、本地可用资源、Python 测试与 SDF。没有 Gazebo 的 CI 使用 `CUADC_SKIP_SDF=1`；资源缺席时相应专用测试明确跳过。检查结果写入 `dist/validation/`，不把跳过记为完整仿真通过。

导出与 GitHub 发布步骤见[开源发布说明](开源发布说明.md)。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 资源校验提示缺失 | 按资源说明准备有权使用的模型和图片；源码不提供自动下载 |
| 模型校验失败 | 核对文件来源与版本；替换后更新清单并重新验收 |
| `MISSION_INVALID` | 检查场地与航线配对、指令序列及完整上传情况 |
| `RECOGNITION_FAILED` | 核对相机帧、模型、目标尺度与检测记录，不使用固定答案兜底 |
| 上传返回 `NO_SPACE` | 检查是否有另一 SITL 实例与端口冲突，结束该次仿真后重试 |
| Gazebo 黑屏或无法显示 | 检查显示会话、OpenGL 与驱动；无图形模式只用于辅助定位 |
| 再次启动端口被占用 | 核对残留 PID，关闭属于前一次测试的进程 |
