# 开源发布说明

推荐发布整个仓库的干净源码导出，保留仿真、机载和地面站之间的文档与测试关联。不要直接压缩本机工作目录，也不要把旧仓库推送到公开远端。

## 1. 发布范围

`scripts/release_policy.py` 定义公开目录与排除规则，`privacy_audit.py` 检查公开文件内容。导出不会复制 Git 历史、环境、运行记录、真实航线、未明确授权的靶标或衍生数据；两套已审核的运行权重归档会随公开源码导出。

保留在本机的靶标图片和训练资料供既有环境继续运行。Git 忽略不等于文件已经删除，因此整个工作目录不适合作为公开压缩包。只上传干净 Git 快照或导出的源码包。

运行权重归档会进入本次源码导出；训练数据、训练记录和未授权素材不通过源码或 Release 附件分发。详见[资源与许可](资源与许可.md)。

## 2. 检查与导出

```bash
./scripts/verify_release.sh
python3 scripts/build_release_packages.py public --directory dist/cuadc-public
python3 scripts/privacy_audit.py --root dist/cuadc-public
(cd dist/cuadc-public && sha256sum --check PACKAGE_SHA256SUMS)
```

导出目标已存在时命令停止，防止旧产物混入新版本。重新导出需使用新的目录名。测试报告保存在 `dist/validation/`，维护者应记录执行环境、资源是否齐备、通过与跳过项，以及是否执行完整飞行。

还可构建源码压缩包：

```bash
python3 scripts/build_release_packages.py public
```

输出位于 `dist/public/`，包含压缩包和 `SHA256SUMS`。归档统一文件时间、UID/GID 和文件模式，不带本地用户名和目录路径。包内另有逐文件 `PACKAGE_SHA256SUMS`。

`simulation`、`onboard`、`ground-station` 参数仅供单独导出模块源码；它们不携带完整仓库的操作文档与跨模块检查工具。首次公开发布优先使用 `public`。

## 3. 新建公开仓库

已检查过的工作目录应只有干净的首次提交，不继承旧远端和个人提交身份。若从导出目录建立仓库，可按以下顺序操作：

```bash
cd dist/cuadc-public
git init -b main
git config user.name 'CUADC Contributors'
git config user.email 'contributors@example.invalid'
git add .
git diff --cached --stat
git commit -m 'Initial public source release'
```

公开导出中没有旧 `.git`，不要复制旧仓库的对象、refs、reflog 或配置。提交前复查暂存清单；如果使用个人 Git 身份，GitHub 会公开相应作者与邮箱。

在 GitHub 创建空仓库后，为这个干净仓库手工配置新远端，再推送 `main`。本文不预设账号或仓库地址；公开前确认许可证、文件列表与发布说明。源码导出和本地整理不会自动上传任何内容。

## 4. 发布复核

| 项目 | 要求 |
| --- | --- |
| 版本 | 三模块 `pyproject.toml` 与发布说明一致 |
| Git | 无旧历史、旧远端、个人提交身份与额外 refs |
| 隐私 | 审计通过，人工复查路径、日志、图片与模型元数据 |
| 航线 | 仅公开 SITL 示例，不含真实坐标备份 |
| 许可 | 保留原有 MIT、GPL、AGPL 及第三方声明 |
| 资源 | 附带已审核运行权重；不附带未明确授权的图片、训练数据或记录 |
| 验证 | 区分源码测试、资源检查、完整仿真与实机验证 |
| 下载复现 | 在干净导出中安装测试依赖并运行检查；无视觉模式可启动基础仿真 |

自动审计覆盖已定义的模式与公开文件范围，不能替代对授权、GitHub 账号资料和新增资源的人工核对。CI 的源码测试通过也不意味着缺席的模型和硬件已经验收。
